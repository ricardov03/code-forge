# Concepts

The report has 15 sections. Its last section, `agent_waivers`, lists each agent waiver and whether a later human unwaive cancelled it. The human can undo an agent waiver with `block unwaive` and acknowledge the counted set with `block ack-waivers`. Both ask at a terminal and have no `--yes`. Set `review.agent_waivers.require_ack: true` before run start to require that acknowledgement before close. A new or removed waiver needs a new acknowledgement. Human waivers are never undone by this command.

A glossary. Each term links the idea to the command or config key that makes it real.

| Term | Meaning | Where you see it |
|---|---|---|
| **Brief** | A short text that says what to build. The input to the Plan job. | `plans/<name>.md` |
| **Facts sheet** | Every claim in the brief (flags, paths, versions, commands, env names) checked by an L0 delegate with a read-only command, tagged VERIFIED, NOT-FOUND or UNVERIFIABLE, with the command and its output line. The delegate works on a read-only snapshot of HEAD, so uncommitted files are invisible unless passed with `--sources`. | `code-forge facts` → `plans/<name>.facts.md` |
| **Plan** | The L3 draft: design, blocks, a caller map, acceptance clauses, forecasts. Its §0 is the facts sheet, verbatim. | `code-forge author --job plan` → `plans/<name>.plan.md` |
| **Block** | One deliverable of the plan, coded by one coder and closed by one gate. Ends in one commit. | `code-forge block open <id> …`, `block close <id> …` |
| **Owned files** | The exact paths (or disjoint globs) a block may change. Blocks that run together never share one. A changed file outside the set is an *orphan* and stops the gate. | `--owned <paths…>`, `block claim <id> <path>` |
| **Acceptance clause** | One testable sentence of a block. Each clause names at least one test id (`<file>::<case>`). | `--acceptance <file>` (YAML or JSON list of `clause` + `tests`) |
| **Level** | A rung of the model ladder: `L0` small, `L1` medium, `L2` high, `L3` top. The config maps each level to provider, model, effort and fallbacks. Skills name levels, never models. | `levels.L0`…`levels.L3`, `code-forge resolve L<n>` |
| **Lane** | The level S1 picks for a block's coder: `L0`, `L1`, `L2`, or `split` (too big). L3 is never a lane. It is recorded per block, and `plan check` refuses a block whose level is not its recorded lane. Without Jev, `--rules` answers from the block's size and paths. In a brief-mode run, `block open` without `--level` takes the rules lane itself. | `code-forge jev ask lane --block <id> --plan <file> --state <file> [--rules]`, the `lanes:` line of `plan check` |
| **Running level** | The level a coder actually runs at. It starts at the lane and climbs one step per escalation. **L2 is the highest running level.** | `dispatch` and `escalation` ledger rows |
| **L3 rung** | The step above L2: one fresh L3 session writes a patch of at most 80 lines in the owned files, once per block. Then the block continues at L2. | `escalation.l3_mode: patch` (default) |
| **Block kind** | `code`, `docs` or `contract`, read from the owned files' endings: only `.md`, `.mdx`, `.rst` or `.adoc` files ⇒ `docs`; only docs and contract files (JSON schemas, `.proto`, `.graphql`, OpenAPI), at least one contract ⇒ `contract`; anything else ⇒ `code`. A docs or contract block is never coded below `levels.coder_floor_docs` (default L1) and skips multimodel review unless `review.multimodel_for_docs` is on. | `block open … --kind code\|docs\|contract` |
| **Heavy round** | A review round that leaves 2 or more open warnings (or any critical) at a level below L2. After one such round the next fix runs one level up. | `escalation.after_rounds_with_warnings`, `escalation.warning_threshold` |
| **Tier** | The proof class of a file. **High** when S1 risk ≥ 2, a `proof.tiers.high.paths` match, or security-sensitive. Otherwise **light**. | `code-forge proof tier --file <path> --risk <0-3>` |
| **S1 (System 1)** | Jev, a small fast classifier model from TypeSafe. Returns an answer plus a probability in about half a second. Never writes code or prose. | `code-forge jev ask <question-id> --state <file>`, `keys.jev` |
| **S2 (System 2)** | A fresh L3 session that checks or makes a decision when S1 is not sure (confidence below `act`, default 0.90, or a small margin). | `code-forge s2 --packet <file>` |
| **Closed book / open book** | A closed-book session sees only the packet on stdin, in an empty folder, with no tools. Reviewers, judges, S2 and the plan author are closed book. Codex always has a shell, so it can only run them *open book* (it could read files on your machine); code-forge refuses that unless you set `review.allow_open_book_codex: true`. | `closed_book` in `code-forge resolve L2`, the `doctor` isolation row |
| **Judge** | An L3 session that reads two review reports and rules which findings are real. In multimodel mode it comes from a third provider. | `review.multimodel`, `review.judge_sees_diff` |
| **Plan approval** | Your yes to a plan that passed `plan check`, given in the harness's plan mode (Claude Code: EnterPlanMode → ExitPlanMode). No block starts before it. Never delegated to autopilot. | the skill, `skill/references/plan.md` §4.1 |
| **Owner rule** | A rule only you change. The orchestrator and the autopilot delegate never change, relax or remove a limit, threshold, budget, gate, forbidden command or review requirement on their own: when one blocks work they stop, show the data, propose options and wait (skill rule R17). | `skill/references/rules-core.md` |
| **Orchestrator** | The session you talk to. It dispatches, re-measures and records. It never codes, reviews or judges. | the skill, `skill/SKILL.md` |
| **Worker** | The background process that serves review tickets, runs closed-book sessions and signs ledger rows. Started only by `run start`. | `code-forge worker` (never by a coder) |
| **Finding severity** | A reviewer's finding is triaged into **fix now** (`fix_now`: must be fixed before the file is approved), a middle band sent to an L3 ruling, or a **nit** (logged, not blocking). A critical finding is always fix now. A finding raised outside a fix hunk in a re-check is a **late finding**, ruled at `block close`. | `thresholds.findings.fix`, `.nit`, `.resolved`; `review.late_findings` |
| **Fix round** | One review pass on a file. Round 1 is the full tiered review; round 2 and later re-check only the fix hunks. The open `fix_now` set must shrink each round. Fix rounds are one per block: wait for every `review-file` ticket of the block and its tests, then send ONE fix message with every failing test and every open finding; a finding that arrives later waits for the next round (`skill/references/code.md` §4). One block round is one round for each file it touched. | `review.round` ledger rows |
| **Review cap** | The most rounds a file gets: `review.max_rounds_per_file`, default 4 (range 2–6). Then the L3 rung once, then `stopped: review_cap` for the human. | `review_cap` in `report` |
| **Review pool** | The worker reviews up to `review.parallel_tickets` files at once (default 3), oldest first. The same file is never reviewed twice at once. | `review.parallel_tickets`, the `doctor` row `review concurrency` |
| **Provider limit** | The most review sessions one provider runs at once. A session waits for a free slot. Defaults: anthropic 4, openai 2, xai 2. | `review.provider_concurrency` |
| **Backoff** | The wait before a rate-limited session tries the same step again: about 2 seconds, then about 6. | `review.unavailable` rows, `logs` warnings |
| **Reservation** | The estimated cost a running session holds against `budget.usd` until its row is written. It keeps parallel sessions from spending past the budget. | `budget.usd`, the budget refusal text |
| **Review-only** | A review of changes you already have, with no plan, coder, proof or block close. It opens one `R-<timestamp>` block at L2 for the changed files, reviews each file, then stops the block and ends the run. Exit 0 only when every file is approved. | `code-forge review`, [review-only.md](review-only.md) |
| **Waiver** | A decision to accept an open finding or an unproven high-tier file. A human waiver is signed with `by: human`. An agreed agent waiver is signed with `by: agent`. A coder is never told to run it, and the coder forbidden list denies it where the coder's CLI loads deny rules; the block close grep of the coder's transcript fails the gate when it appears. `block reopen --yes` needs evidence and agreement from a fresh judge, at most once per block and file in a run. Critical or unknown-severity waivers still need the human. The orchestrator prints the command; the human runs it in their own terminal. `block waive --yes` exists for a recorded warning or nit finding with evidence and a fresh judge. The judge must agree. An autopilot grant does not change the human paths. The prompt checks only that stdin and stdout are terminals; a pseudo-terminal passes it, so it does not prove a human (`skill/references/security.md` §3). A file whose review stopped or refused counts as reviewed: its status is `reviewed_by_waiver` instead of `unreviewed` (it is never approved), and a successful close writes one signed `gate.review_waived_all` row for it just before `block.close`. That needs a signed review round on the current content, a latest signed refusal for that content that names at least one finding, and every named finding and every open `review.cap` id cleared. A critical needs a human waiver. An accepted agent or autopilot waiver may clear a warning or nit. The row records `by` as `human`, `agent`, or `autopilot`. | `code-forge block waive <id> <finding-id> --run <r> --file <path> --reason <text>` |
| **Autopilot grant** | Your time-boxed permission (at most 24 h) for a delegate to make some of your decisions in one run: the scopes it may decide, the delegate's level, the budget caps and the end time. One per run; it ends at `--until` or when you stop it. | `code-forge autopilot start\|status\|stop`, `autopilot.grant` rows, [autopilot.md](autopilot.md) |
| **Delegate** | A fresh closed-book L2 or L3 session (never Codex) that answers one owner question inside the grant by picking one of the given options. Its answer is acted on only when it is in scope, does not escalate, and its confidence is at least `autopilot.min_confidence` (default 0.7); otherwise the question goes to you. | `code-forge autopilot ask`, `autopilot.decision` rows |
| **Scope** | One kind of decision a grant can allow: `waive:warning`, `waive:nit`, `round:extra` (one fix round past the cap), `model:choose` (the coder level). | `--allow`, `--deny` |
| **Deny list** | The decisions autopilot can never make, fixed in the code: critical and proof waivers, skipping reviews, any limit or rule change, plan and design approval, merges, destructive actions, budget raises. | the `deny` line of `autopilot status` |
| **Approval** | Your own temporary change of one setting during a grant. It comes back by itself at the time you give. Only at a terminal, never with `--yes`. | `code-forge autopilot approve`, `autopilot.approve` and `autopilot.restore` rows |
| **Binnacle** | The summary of an autopilot run: status at a glance, decisions with what would reverse them, blocks, open questions, actions only you can take, incidents, timeline. The first tab of the live log doc, or `autopilot-binnacle.md` in the run dir. | `code-forge autopilot binnacle --run <r>` |
| **Full log** | Every autopilot event of a run, one row per signed ledger row, newest first. The second tab of the live log doc, or `autopilot-log.md` in the run dir. | `code-forge autopilot log --run <r>` |
| **Project root** | The folder that gives a project its config and ledger, so any verb gives the same result from any subfolder. It is the nearest `.code-forge.yml` up to the git top level, else the git top level. Outside git, the search never goes above your home folder. | `project.slug`, else the project root's folder name |
| **Ledger** | The append-only event log per project: one JSON row per dispatch, review, decision, proof, escalation, stop. Gate-relevant rows are signed. Never committed. | `~/.code-forge/ledger/<slug>.jsonl`, `code-forge ledger tail --slug <slug>` |
| **Outside review** | Review rounds a PR got outside code-forge (a human or a review bot), recorded by the orchestrator or owner. A later record for the same PR replaces the earlier one in `report`. The `outside_review` report section puts each PR's rounds and findings next to the code-forge cost of its blocks. | `code-forge ledger outside-review --run <r> --pr <n> --rounds <n> --findings <n> [--link <url>] [--block <id>]…`, a signed `outside_review` row, `outside_review` in `report` |
| **Budget** | The spend limit of a run in US dollars. Each session row carries an estimated `usd` from a price table. At 80% you get one warning; at 100% no new session starts (and if the spend cannot be read, none starts either). Spend code-forge did not see is added by hand. | `budget.usd`, `code-forge run status`, `code-forge report`, `code-forge ledger add coder --usd <n>` |
| **Signed row** | A ledger row carrying an HMAC made with the per-run key in `~/.code-forge/runs/<run>.key`. `block close` trusts only rows whose MAC verifies. Same-user boundary only. | `mac` field, `ledger.tamper` row |
| **red→green** | Red→green: each new or changed test must FAIL on the old code first (red), then PASS on the new code (green). A red caused by an import, compile or crash error proves nothing; the red must be an assertion failure. | `code-forge proof red-green <block> --run <r> --test <file::case>` |
| **Proof row** | A signed `proof` ledger row from the red→green runner: the test failed with an assertion against the base code (`red_kind: assertion`) and passed against the new code. Required at `block close` for each changed high-tier file. A test that is not a `node:test` file is run by a `proof.runners` entry and read from its JUnit report; the row then adds `runner` and `failed_tests`, a bounded list of test names (at most 20, each cut at 200 characters, control characters removed). The full list of failed ids (`failed_ids`) is never stored. | `code-forge proof red-green <block> --run <r> --test <file::case>` |
| **Measurement export** | A clean copy of the block at its base sha plus its owned files, where gates and red→green run so parallel blocks do not disturb each other. Dependency folders are linked from the main tree, except a Composer `vendor`, which is copied so PHP loads the export's own classes. Verified on Node (`node:test`) and on Laravel with PHPUnit and with Pest; `proof.isolation: lock` is the fallback. | `code-forge proof export <block> --run <r>`, `.code-forge/export/<block>/` |
| **Worktree isolation** | `proof.isolation: worktree` gives each block its own git worktree on its own branch (default `../<repo-name>-worktrees/<block>` on `forge/<run>/<block>`), made by `block open` before the block is recorded. Two blocks that each have a worktree may own the same path. `block close --remove-worktree` removes the tree and keeps the branch. Nothing is pushed or merged. The setting is fixed for the run. The coder works in the tree: gates, reviews and the close check of the block run there and see only its work, never the main checkout's or another block's (a `--cwd` other than the tree is refused). | `proof.worktree.dir\|branch\|base`, `worktree.created`, `worktree.removed`, `worktree.remove_failed` rows |
| **Context pack** | One file per block, `<run-root>/context/<block>.md`, that the orchestrator sends with every coder task: the block header (run, block, level, owned and test files, worktree), the project's build, test, lint and format commands as argv text (never run), the rules files and the lessons file, cut to `context.max_lines`: the lessons are cut first, then the rules files from the last one backwards; the header and the commands are never cut; each cut section ends in `[cut: N lines dropped]`. Review packets carry the same rules and, under a `### lessons` subheading, the lessons in their project-rules slot, all inside its one 60-line cap. Rules and lessons are read from the main tree; `context` is not authority and is read from the live config, so `run reload` accepts a change — except `context.require_coder_tests`, which makes `block close` need the coder's `TESTS <command> exit=0` line, is read from the run's snapshot and is fixed for the run. With no `context` key the review packets are unchanged and `context pack` refuses (exit 1). | `context.*`, `code-forge context pack --run <r> --block <id>`, `context.pack` rows |
| **Gates** | The project's `test`, `lint`, `types` and `format` commands, detected by `init` (stacks: `php-pest`, `php-phpunit`, `node`, `rust`, `python`, `go`) and stored as argv arrays, or as `{argv, env}` to add environment variables (code-forge shows only their names; env is not a secret store). An argv item that is exactly `{test_files}` runs only the block's related tests (its `--tests`, else its owned test files), or the full suite when the block owns more than `gates.full_suite_threshold_files` owned files (globs and directories count the tracked and new (not ignored) files they cover) or no test file is known. | `gates.*`, `code-forge gates detect\|run`, `block open --tests` |
| **Run** | One orchestration session with a worker, a signing key and a run record. Every block belongs to a run. | `code-forge run start\|status\|end` |
| **Status** | The short, read-only progress view of the runs of this repository that are not ended, at most 10 lines per run (runs separated by a blank line; `--json`: one line). Line 1 gives the run's status, its mode and the spend (`spent $<x> of $<budget>`). Then one line per open or in-attempt block: its state (`open` or `attempt-<n>`), level, coder model, last gate and open findings. When the blocks do not fit, the last block line is `… +<k> more blocks`, and `closed <a> · stopped <b>` follows when either is non-zero. With no such run it prints `no active run`. The orchestrator checks it instead of reading logs or polling transcripts. Every block verb also takes `--json` (one JSON line on success). | `code-forge status [--run <r>] [--json]`, `block <verb> … --json` |
| **Block end** | Every close or stop of a block (`block close` that closes it, or stops it on a pin event or `ledger.tamper`, and `block stop`) writes a done file, `<run root>/blocks/<id>.done.json` (the run's state folder `~/.code-forge/runs/<run>/`), atomically and after the end's rows: `block`, `run_id`, `status`, `event`, `reason`, `commit`, `spent_usd`, `unknown_usd_sessions`, `findings`, `at` (`commit`, the spend and `findings` are null when they cannot be read) — never transcript, diff text or secrets. With `hooks.on_block_end` the owner's command then runs once, outside the run lock and outside coders (no shell, cwd = repository top, stdin closed, output discarded, killed at `timeout_s`), with `CODE_FORGE_RUN`, `CODE_FORGE_BLOCK`, `CODE_FORGE_BLOCK_STATUS` and `CODE_FORGE_DONE_FILE` (the absolute path, or `""` when the file was not written) set, and one signed `hook.ran` row per end. Only with `hooks.on_block_end` set do `close --json` and `stop --json` carry `done_file`: the absolute path, or null when it was not written. The orchestrator waits for the done file or the hook instead of polling. A failed write or hook only warns. The hook is fixed for the run. | `hooks.on_block_end {argv, timeout_s}`, `hook.ran` rows, `done_file` in `close`/`stop --json` |
| **Run mode** | `plan` (the default: facts, plan, check, approval, then blocks) or `brief` (briefs and no plan, for a small change). Set once by `run start` and fixed for the run. In a brief-mode run, `block open` without `--level` takes the rules lane. | `code-forge run start --mode brief`, a signed `run.mode` row, the `run mode:` lines of `report` |
| **Engine** | How coders are started. **`solo`**: Solo processes you can watch (picked by `engine: auto` when Solo is present). **`harness`**: the harness's own subagent tool, one coder at a time (Claude Code). **`subprocess`**: detached CLI processes; only when you write `engine: subprocess` yourself. Reviews run the same way in every engine. | `engine` key, printed by `run start` |
| **Harness** | An agent tool the skill is installed into: Claude Code, Codex CLI, Grok CLI, Gemini CLI, Cursor, Copilot. | `code-forge init --harness a,b`, `code-forge list` |
| **Push and PR autonomy** | Whether a coder may push its block branch, and open a **draft** PR, on its own. Both are off by default: the coder hands back its branch and the orchestrator (or you) push. A draft PR needs a push, so it is allowed only with push on, and only after the block's independent reviews pass. Marking a PR ready is the orchestrator's job; merging is yours. | `autonomy.coder_may_push`, `autonomy.coder_may_open_draft_pr`, `init --coder-may-push yes\|no --coder-may-open-draft-pr yes\|no` |
| **Sentinel** | The line that ends a coder's turn: `===BLOCK <id> COMPLETE===` or `===BLOCK <id> FAILED: <reason>===`. | the coder's report or log |
| **Pointer** | The short message a coder receives: `BRIEF <path> lines=<n> sha=<sha8> <<<EOM>>>`. The coder must answer `ACK <sha8> lines=<n>` first, so a truncated message is detected. | printed by `block open` |
| **Forecast** | The coder's estimate of test cases and net lines. Over 1.25 × the line forecast stops the block and asks for a split. | `block open --lines <n>`, `forecast_vs_actual_lines` in `report` |
| **Coder report** | The coder's final message, ending with its sentinel. The final report needs no `reviewed <path> ticket <id>` lines: `block close` prints one for every file the review gate accepts (approved, waived or answered), with the queue's ticket. The close prints the reviewed lines, then the `reviewed_by_waiver` lines, then the `closed` line. With `--report`, a hand line that names another ticket prints `WARN report ticket mismatch <path>` on stderr when the block closes, and the close goes on. A file with a `review.waived` finding still gets a line; only a close with every review waived (`--no-require-reviews`) or `review.external` prints none. The printed line has no `via`: `--json` and the block's done file carry the lines as `reviewed: [{file, ticket, via}]`, with `via: approved` for a file with a signed approval, `via: waiver` when at least one of its open findings was waived (also when the others were answered), and `via: answered` when every one was answered. Just before the sentinel the coder's report carries `TESTS <command> exit=<n>` (`<n>` a decimal 0–255, no leading zeros; the last such line after the previous sentinel counts). With `context.require_coder_tests`, close refuses a report without that line or with an exit that is not 0, and a close that passes writes a signed `coder.tests` row. | `block close <id> --run <r> --report <file>`, `skill/templates/coder-brief.md` |
| **Config reload** | Re-reading `.code-forge.yml` into a running run, so open blocks keep going. Keys fixed for the run (`project.slug`, `engine`, `tmp.root`, `keys`, `system1.key`, `review.external`, `context.require_coder_tests`, `version`) are refused by name. While an autopilot grant is active, limit keys are refused too. | `code-forge run reload --run <run>`, a signed `run.reload` row |
| **Error log** | One line per failed verb in `~/.code-forge/logs/errors.jsonl`, cleaned before it is written: flag names but never values, no home folder, project name or 1Password references. Nothing leaves your machine unless you send a report. | `code-forge logs`, [privacy.md](privacy.md) |
| **Warning** | A problem code-forge recovered from on its own: a 1Password retry, a review retried after a timeout, System 1 falling back to rules, the 80% budget warning. Logged as `kind: warning`, shown by `logs`, and left out of a report unless you ask. | `code-forge logs report --include-warnings` |
| **Breadcrumbs** | The names of your last 5 commands (the verb and its subcommand word, never a flag or a value). Each logged error lists them as `before`. | `~/.code-forge/logs/breadcrumbs.json` |
| **Fingerprint** | 12 characters that stay the same when the same error comes back with other numbers, names or paths. It groups errors in `logs` and finds an earlier issue for a report. | `code-forge logs`, `logs summary` |
| **Known fix** | An error fingerprint that a released version already fixes, in a table shipped with the package. `logs` marks it `[fixed in X.Y.Z]`; on an older version `logs report` tells you to upgrade instead of filing it. | `code-forge logs report [--force]`, [releasing.md](releasing.md#record-a-known-fix) |
