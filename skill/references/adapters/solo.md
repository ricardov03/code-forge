# Solo adapter — engine `solo`

Solo adds spawn, watch, timers, scratchpads, locks and `kv` on top of the CLI; it is not what isolates sessions (the worker does that in every engine). `forge run start` runs before the first spawn; `forge block open` runs before **every** spawn.

## §1 Once per machine: measure the input limit

`send_input` truncates silently. Before the first real spawn on a machine, send a throwaway L0 process four payloads of 1 200 / 1 600 / 2 000 / 2 400 bytes, each beginning with a known marker and ending in `<<<EOM>>>`, and read back which arrive with both ends intact. Write the largest intact size to `kv forge:solo_input_limit` and to `~/.code-forge/cache/solo-limit.json` (`{bytes, measured_at, solo_version}`). Every later first message is capped at `limit − 200` bytes; until measured, the cap is 1 200 B. The pointer itself stays ≤ 200 B.

## §2 The wire: pointer, sentinel, receipt

1. Long instructions live in the brief file; the wire carries the pointer `forge block open` printed — `BRIEF <path> lines=<n> sha=<sha8> <<<EOM>>>` — after the agent's own instructions, nothing more.
2. Every wire message ends in `<<<EOM>>>`. No sentinel ⇒ truncated ⇒ the receiver does not act, says so, asks for a resend. A coder that refuses half an instruction is correct.
3. The receipt: the coder replies `ACK <sha8> lines=<n>` **before any tool call**. The launch gate reads `get_process_output(lines=40)` for it; no ACK or a wrong sha ⇒ clear the input box, resend once; still none ⇒ `parked`, respawn once, then `failed`. **Clearing is sized, then confirmed:** a fixed number of deletes can leave the front of a long payload in the box, and a resend appended to that junk still ends in `<<<EOM>>>` and passes the sentinel check. Send a kill-line sequence when the agent's input supports one; otherwise send as many DELs as the largest possible payload — the measured limit of §1, or 2 400 B when it has not been measured — and then read `get_process_output` to confirm the input line is empty before resending. A box that will not empty is a `parked` coder, not a resend target. `search_output` looks for the ACK line during idle triage.
4. Every dispatch or GO names the plan file, its revision and its line count; the coder echoes them back. Unsent text in a coder's input box is never an instruction: clear the box before every send.

## §3 Spawn protocol per block

1. Pre-flight: `list_processes` and close **only** agents this run spawned (own pids only); `list_agent_tools` to resolve runtime ids live, never from memory. Never more than `caps.coders` coder processes alive; a further spawn waits for a completion wake, never for a timer.
2. `forge block open <id> --run <r> …` (`code.md` §3), then `spawn_agent(agent_tool_id=<coder runtime>, name="coder-<id>", extra_args=<the argv the level resolves to>)` — the model, effort and permission mode are pinned **at spawn** from `forge resolve L<n>` and the provider's coder flags (`forge spawn --level L<n> --role coder --brief <file>` prints the exact argv without running it when you need to see it); never a post-boot model switch. Coders run in the provider's non-interactive auto mode: a session parked at a permission prompt is the first failure mode of every run.
3. First `send_input` after the `❯` prompt: the agent's instructions, then the pointer (§2).
4. **Launch-verification gate** — the one thing you babysit: poll `get_process_output` / `search_output` until the coder shows the ACK and tool activity. Dead-idle after the pointer (no prompt on screen) ⇒ one Enter (`send_input bytes=[13]`) and re-check. A **permission or model-picker prompt** is never answered with Enter — it would accept an unreviewed default: `close_process`, respawn with the correct `extra_args`, and record a `spawn-flag defect` line in the block record (the flags came from `forge resolve`; a prompt means they were not pinned).
5. **Wake channels, event-driven, never fixed polls:** record your own pid once (`whoami` → `kv_set("forge:orchestrator_pid")`); coders that can call Solo carry the push contract (post-sentinel `kv_set("block:<id>", …)` + `timer_set(1s, body, delivery_process_id=<your pid>)`); for every group arm `timer_fire_when_idle_any([coders], max_wait≈20–25 min, delivery_process_id=<your pid>)` right after the launch gate (idle-any ignores already-idle processes, so arm while they are provably running); keep one long dead-man fallback per 30–40 min with an L0 triage first. On wake: sentinel ⇒ gate; no sentinel and active again ⇒ re-arm; no sentinel and idle ⇒ parked, intervene now.
6. Completion = `search_output(pattern="===BLOCK <id> COMPLETE===")`, last occurrence (the `kv` key is the truncation backup). Completion is not closure.
7. **Review rounds, with the coder still alive.** The coder ran `forge review-file <path> --block <id> --run <r>` per file and `--wait`ed on each ticket; read the ledger (`forge ledger tail --slug <slug>`) for what is still open — a `fix_now` finding, a `pending` ticket, a file never submitted. Each open finding is a fix round sent to the **warm coder** by `send_input` (the findings by id, `<<<EOM>>>`), which fixes and re-runs `review-file` on that file; round ≥ 2 re-checks only the fix hunks (`review.md` §5). **One ladder** (`decisions.md` §5): a stall or exhausted rounds *below L2* climbs one level — close this coder and respawn a fresh one at the higher level with the open findings and the fix history in its brief; **the respawn keeps the per-file round count**, the cap does not reset. L2 is the highest running level: a trigger at L2, or the four-round cap on a file, goes to the **L3 rung once** — a fresh L3 patch session, never this coder and never a coder at L3 — and if findings stay open after the `patch_check` round the file is `stopped: review_cap` for the human. No other path exists.
8. **Close** only when every changed file has a signed `review.approved` row: the re-measurement of `code.md` §5, then `forge block close <id> --run <r> --report <file>` (the coder's final report) — the transcript grep reads the Solo output. Closing with a file still unreviewed is a human decision, audited: `forge block waive <id> <finding> --run <r> --file <path> --reason "<why>"` per finding, or `forge block close … --no-require-reviews`.
9. **Reap after the close**: `close_process` the coder and confirm `lock_status` shows no lease before the next group. Locks: a coder that can call Solo holds `lock_acquire` on its file area while editing; coders that cannot never overlap another block.

## §4 Latency overlaps (standing)

Draft block N+1's brief while N codes; dispatch the gate the moment the sentinel lands; keep the coder alive until its last review round (fix rounds go to the warm coder); spawn-ahead N+1 during N's review when N+1 depends only on interfaces that already passed N's gate — never for a security-keystone block.

## §5 State in Solo

Plan and research digests → scratchpad sections, read back selectively (`scratchpad_read` on a section, `scratchpad_tail`); block state → todos with `todo_set_blockers` mirroring `depends_on`; small shared facts (branch, slug, runtime ids, the input limit) → `kv`; long agent output stays in the process (`search_output`, never a full dump). The handoff log and the run record still exist (`continuity.md` §1): Solo is the convenience, not the only copy.
